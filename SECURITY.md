# Security and privacy

For a vulnerability, use GitHub private vulnerability reporting if enabled; otherwise contact the repository owner privately before disclosing credentials or exploit details. Do not post live proxy passwords, tokens, cookies or identifying reports in public issues.

This tool makes low-frequency user-initiated measurements. It does not bypass CAPTCHA, authenticate accounts, change DNS/firewalls or scan arbitrary port ranges. Providers receive the tested IP and ordinary request metadata; commercial sources require opt-in authorization. Reports stay local. `--redact` masks IP/hostname and disables screenshots; review remaining page content before sharing.

Use trusted GitHub release URLs and verify SHA256SUMS before executing. Release archives include a Node runtime and production dependencies; browser dependencies are isolated and optional. SSH Agent requires existing host-key trust and user authorization; host-key checking is never disabled. `--no-install` and `--offline` prohibit automatic downloads as applicable.

Only managed installation resources are removed by uninstall. System Node/curl/browsers, network configuration, repository source, reports and API keys are preserved by default. Database absence, HTTP200 and a passing score cannot prove a clean IP, permission to register, or future access.
